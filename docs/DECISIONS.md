# Журнал решений

Короткие записи «решение — причина». Без данных организации (T36): значения установки живут только
в `config/connection.json` и диспетчере учётных данных.

## W1 — ядро очистки

- **Рантайм net48.** Официальная EWS Managed API 2.2 — сборка под .NET Framework; .NET 8 выходит из
  поддержки 10.11.2026. Сборка без установленного Developer Pack — через NuGet
  `Microsoft.NETFramework.ReferenceAssemblies`.
- **Мультиарендность (T36).** Ни адреса, ни ящика, ни пояса, ни отпечатка в коде/документах/тестах/логах.
  Всё — через `ConnectionProfile` из `config/connection.json`. Тесты на синтетике.
- **Пояс — фиксированное смещение (T31)** в `TargetTimeZone`, значение из конфигурации. Не полагаемся
  на таблицы поясов сервера; DST — вне объёма (YAGNI).
- **`TimeMapper` только нормализует к UTC**; работа с поясом и периодом — в `TargetTimeZone` (SRP).
- **401 никогда не повторяется (T3).** `ErrorClassifier`: Authentication и Permanent — без повторов,
  Transient — с ограничением, VersionConflict — ровно один повтор.
- **Удаление только по полному снимку (T30, T32).** `CompletenessGuard`: постраничный обход полон лишь
  при пометке последней страницы и совпадении числа элементов; пакетное удаление успешно лишь при учёте
  всех id (`ErrorItemNotFound` — идемпотентный успех, частичный результат — ошибка).
- **Семантика периода (§8).** Одиночное — по пересечению с окном; серия целиком внутри — удаляется
  мастером; серия на границе — обрезается (только повторения в окне); бессрочная серия — всегда обрезка,
  не удаление целиком.
- **Дефолт очистки (T27).** R1 — только режим «все события» (наследие прежнего приложения метки не
  несёт). Режим «только копии моста» — для R2, станет дефолтным там.
- **Порты отложены до W2/W3 (YAGNI).** Пока адаптера нет, интерфейсы были бы догадками; ядро очистки
  чисто функциональное и тестируется без них.

## W2 — адаптер приёмника (EWS)

- **Исправлен дефект классификации серий на границе периода.** Членство считается по интервалу
  повторения (с длительностью), а не только по времени начала; при неоднозначности — обрезка, не пропуск.
- **Закрепление сертификата — TOFU (`CertificatePinningPolicy`).** Нет отпечатка и цепочка доверенная →
  принять и запомнить. Есть отпечаток → сверять. Несовпадение имени с адресом игнорируем (подключаемся
  по IP, сертификат на имя сервера). Перехват HTTPS (издатель-антивирус/прокси) → отдельная понятная
  ошибка, а не «пин не совпал».
- **Граница с сетью при чтении — один порт `ITargetPageReader`.** Весь цикл/дедуп/полнота — в
  `CalendarSnapshotReader` (Core, тестируется без сервера). Это держит EWS Managed API в одном тонком
  классе-реализации (SoC) и исключает гонки/зависания в оркестрации.
- **Ещё не сделано (нужен живой сервер):** реализация `ITargetPageReader` и удаления на EWS Managed API
  (транспорт NTLM/TLS1.0 + callback пина), контрактные и интеграционные тесты против тестовой подпапки.

## W2 (часть 2) — решения по адаптеру EWS

- **`ExchangeService` с `TimeZoneInfo.Utc`.** Сервер отдаёт времена в UTC — снимает ловушку пояса при
  чтении (членство в окне считается в UTC). Пояс записи (R2) решается отдельно через `MeetingTimeZone`.
- **Удаление `DeleteItems` + `SendCancellationsMode.SendToNone`.** Для элементов календаря атрибут
  обязателен; `SendToNone` не рассылает отмены. Пер-элементные исходы → `DeleteResult`,
  `ErrorItemNotFound` = идемпотентный успех.
- **Учётные данные — `CredReadW` (P/Invoke).** Пароль хранит Windows (DPAPI), приложение его не
  сохраняет. Цель по умолчанию `IwoCalendarBridge/ews`.
- **`EwsErrorMapper` сужен до заведомо существующих кодов `ServiceError`** (AccessDenied, ServerBusy,
  QuotaExceeded, IrresolvableConflict, SchemaValidation; прочее → Unknown); транспортные исключения —
  через `WebException`/HTTP-статус (401 → Authentication, 413 → RequestTooLarge).
- **`Task` неоднозначен** (у EWS свой тип `Task`): вызовы TPL квалифицированы `System.Threading.Tasks.Task`.
- **Границы с сетью не покрываются модульно.** `EwsCalendarGateway`, транспорт и `WindowsCredentialStore`
  проверяются интеграционно; вся тестируемая логика (мапперы, оркестрация) вынесена в чистые классы.

### Ещё не сделано в W2
- Загрузка границ серий (`FirstOccurrence`/`LastOccurrence`) через `GetItem` для режима «период».
- Обрезка серий на границе через `CalendarView` (удаление повторений в окне).
- Интеграционные тесты против тестовой подпапки (нужен живой сервер, Kaspersky off, `config/connection.json`).

## W2 (часть 3) — серии и обрезка границы

- **Сопоставление повторений с сериями — по UID.** Повторение из `CalendarView` несёт `calendar:UID`
  (проверено: возвращается на Exchange 2007), мастер получает UID через `GetItem`. Обрезаем только
  повторения серий с нужным UID; «внутренние» серии удаляются целиком мастером, одиночные — сами,
  пересечений нет.
- **Границы серий (`FirstOccurrence`/`LastOccurrence`) — отдельным `GetItem`.** В неразвёрнутом
  `FindItem` эти свойства не возвращаются; нужны только в режиме «период».
- **`CalendarView` с дроблением окна (T15).** Усечение → деление окна пополам до суток; неустранимое
  усечение внутри суток → результат неполный, обрезка отменяется (не теряем данные).
- **DRY.** Пакетирование вынесено в `Batching.Chunk<T>`; удаление повторений переиспользует
  `CleanupExecutor` (строгая оценка, отказ по неавторитетному снимку).
- **Разделение путей очистки серий:** «внутри периода» → удалить мастер; «на границе» → `SeriesTrimmer`;
  «весь календарь» → обрезка не применяется (серии уходят мастерами).

### Остаётся в W2
- Интеграционные тесты против тестовой подпапки: перечисление, `GetItem` границ/UID, `CalendarView`,
  удаление (нужен живой сервер, Kaspersky off, `config/connection.json`, пароль через `cmdkey`).

## W3 (часть 1) — сценарий очистки и ревизия W2

Ревизия собственного кода W2 нашла дефекты; исправлены и закрыты регрессионными тестами:

- **Граница периода в CalendarView.** По документации CalendarView исключает только элементы, закончившиеся
  *раньше* начала окна, то есть экземпляр, закончившийся ровно в начале периода, возвращается — и удалялся бы
  при обрезке. Введено единое правило `TimeWindow.Overlaps`, ответ сервера всегда дофильтровывается им.
- **Одиночное событие с UID серии.** Обрезка сопоставляла экземпляры только по UID и могла удалить одиночное
  (в том числе чужое) событие с тем же UID. Теперь в обрезку попадают только повторения и исключения
  (`AppointmentType`), а UID, совпадающий с UID сохраняемой серии, даёт пропуск с причиной.
- **Исключение, перенесённое за период.** Серия «целиком в периоде» по правилу удалялась мастером вместе с
  перенесённым за период исключением. Теперь читаются `ModifiedOccurrences`, и такая серия обрезается.
  Исключение, перенесённое *в* период, делает серию граничной (по факту из окна).
- **Бессрочная серия** определяется по `Recurrence.HasEnd`, а не по вычисленному сервером последнему повторению.
- **Предпросмотр ≠ выполнение.** Выполнение строило план заново и могло удалить то, чего пользователь не видел.
  Теперь `RunAsync` принимает подтверждённый предпросмотр и удаляет только пересечение подтверждённого и
  свежего; все чтения (включая раскрытие окна) — до первой записи.
- **Пропуск элементов при постраничном обходе.** Проверки числа элементов недостаточно. Применён приём
  «якорного элемента» из документации Microsoft; сортировка по `DateTimeCreated`; повтор обхода при сдвиге.
  Смещение считается от фактического размера страницы (ограничения сервера).
- **Потокобезопасность EWS.** Безопасность экземпляра `ExchangeService` при параллельном использовании не
  гарантируется — все вызовы сериализованы семафором; начатый запрос доводится до конца до освобождения.
- **TLS не задаётся в коде** (рекомендация Microsoft, CA5386): при цели .NET Framework 4.8 действует SystemDefault.
  Фабрика больше не меняет процессные настройки.
- **Валидатор сертификата:** закрепление только для хоста и порта EWS (callback процессный); устранена гонка
  чтения/записи решения (`Volatile`); TOFU атомарно закрепляет SHA-256 на сеанс; SHA-1 из интерфейса Windows
  поддерживается для совместимости; исключения внутри callback дают отказ, а не падение.
- **Отпечаток из диалога Windows** содержит невидимый U+200E — нормализация удаляет символы форматирования
  Unicode и проверяет длину (40/64 hex), опечатка в конфигурации больше не проходит молча.
- **Ложное срабатывание детектора перехвата:** «ESET» совпадал с «Reset». Поиск по границам букв.
- **SecureChannelFailure** означал «сертификат не прошёл», а это ошибка согласования TLS — выделено в
  `TlsNegotiationFailed`. Добавлен тест полноты классификатора по всем видам ошибок.
- **Учётные данные:** `ДОМЕН\пользователь` разбирается на домен и пользователя для NTLM; ошибка чтения
  диспетчера, отличная от «не найдено», больше не выдаётся за «учётные данные не заданы».
- **Учёт удалённого при сбое:** пакетная ошибка сообщает, сколько учтено до остановки.
- **KISS/YAGNI:** отдельный оркестратор `SeriesTrimmer` удалён — обрезка целиком в чистом `CleanupPlanner`.

Мутационная проверка ключевых защит: отключение каждой (якорь, граница окна, перенесённые исключения,
одиночные в обрезке, неоднозначный UID, пересечение с предпросмотром) роняет хотя бы один тест.

## W3 (часть 2) — манифест, загрузчик настроек, архитектурные тесты, CI

- **Манифест удаляемого — порт `ICleanupManifestWriter` в App, реализация `CsvCleanupManifestWriter`.**
  Пишется после свежей сверки и до первого удаления; строки — ровно список удаления (пересечение
  подтверждённого и свежего), данные — из свежего плана. Нечего удалять — манифеста нет. Отказ среды
  (`IOException`, `UnauthorizedAccessException`) — отказ без удаления; прочие исключения не маскируются.
- **Формат манифеста — CSV для человека:** UTF-8 с BOM (Excel и кириллица), CRLF, все поля в кавычках
  (RFC 4180); разделитель — системный разделитель списков (его же берёт Excel при открытии), иначе `;`; время
  в поясе приёмника с явным смещением. Темы приходят извне, поэтому поля, начинающиеся с символа формулы
  (`= + - @`, полноширинные варианты, Tab, CR, LF, в том числе после пробелов), получают апостроф (OWASP
  «CSV Injection»). Апостроф выбран вместо табуляции: файл остаётся пригодным и для программного разбора.
- **Запись манифеста атомарна и надёжна:** временный файл → `Flush(flushToDisk: true)` → переименование;
  имя с UTC-меткой и случайным суффиксом, существующие файлы не перезаписываются.
- **План несёт экземпляры, а не только id** (`CleanupPlan.OccurrencesToDelete`): тема и время экземпляра нужны
  манифесту. `OccurrenceIdsToDelete` вычисляется из них — одно место правды.
- **Тема (`Subject`) — только для показа**, в решениях планировщика не участвует. Читается в `FindItem` и
  `CalendarView` (у исключения тема может отличаться от серии). Копирование мастера при обогащении —
  `TargetItemInfo.WithRecurrence` рядом с полями, чтобы новое поле нельзя было потерять.
- **Загрузчик `ConnectionProfileFile` — в App, не в Core** (разбор файлов — не логика ядра, SoC). Разбор —
  штатный `DataContractJsonSerializer` (без пакетов: System.Text.Json под net48 тянет зависимости и
  binding redirects, Newtonsoft — лишняя зависимость). Проверка значений — только в `ConnectionProfile` (DRY);
  имена параметров конструктора = поля файла, по `ParamName` загрузчик называет поле с ошибкой (закреплено
  тестами).
- **Ошибки профиля не содержат значений полей** (T36): берётся только первая строка текста исключения, где
  .NET Framework значения не пишет.
- **`utcOffset` обязателен, без значения по умолчанию,** формат строго `±ЧЧ:ММ` (разбор вручную: `\d` в .NET
  принимает и нелатинские цифры). Ошибка в поясе сдвинула бы период очистки.
- **Корень файла настроек обязан быть объектом:** сериализатор принимает массив как пустой объект, и
  пользователь получил бы ложное «не задан ewsUrl». Висячая запятая сериализатором прощается — на смысл не
  влияет, закреплено тестом. Незаполненный шаблон (`<host>`) даёт отдельную подсказку.
- **Проверка формы адреса ящика** в `ConnectionProfile`: один «@», без пробелов и «Имя <адрес>». Полную
  проверку делает сервер; здесь ловятся опечатки до подключения.
- **Архитектурные тесты — отдельный проект, белые списки ссылок сборок** через `GetReferencedAssemblies`
  (без NetArchTest — YAGNI). Проверяются фактические ссылки, а не текст .csproj. Новый проект в `src` без
  правила роняет тест. Мутационная проверка: удаление допустимой ссылки из списка роняет тест.
- **CI — GitHub Actions, windows-latest** (тесты выполняются на .NET Framework 4.8). Действия закреплены на
  SHA коммита. Восстановление `--locked-mode` по `packages.lock.json`. SDK 8 закрепляется временным
  `global.json` только на время прогона: в репозитории его нет, локально подходит любой SDK 8+. Скан
  токенов организации в CI не добавлен: сам список токенов был бы данными организации (T36).
- **Не загружать собранные сборки в процесс оболочки** (`Assembly.ReflectionOnlyLoadFrom`): файл остаётся
  заблокированным до выхода процесса и ломает следующую сборку. Ссылки сборок проверяет архитектурный тест.

Мутационная проверка новых защит: игнорирование сбоя записи манифеста и отключение защиты от формул роняют
тесты (1 и 12 соответственно).

## W3 (часть 3) — приложение с окнами (WPF)

- **Совместимость — Windows 7 SP1+, рантайм .NET Framework 4.8.** 4.8.1 на Windows 7 и 8.1 не выпускается; цель
  `net48` была и раньше, документы исправлены. Только системные шрифты и элементы Windows 7 (без значков
  Segoe MDL2 — значок календаря нарисован фигурой). Манифест: supportedOS Windows 7…11, DPI — Per-Monitor V2 на
  Windows 10 1703+, системный масштаб на старых. TLS выбирает ОС; на Windows 7 TLS 1.2 для клиента выключен по
  умолчанию — это объясняет текст ошибки и README.
- **Две сборки по разрядности (x86 и x64)** — `build\package.ps1`: `PlatformTarget` exe, библиотеки AnyCPU,
  отдельные папки сборки на разрядность (инкрементальная сборка не замечает смены `PlatformTarget`), проверка
  разрядности в заголовке exe. `RuntimeIdentifiers` `win7-x86;win7-x64` в проекте окна — SDK выводит их из
  `PlatformTarget`, и восстановление по lock-файлу должно их знать. Переносная папка + zip, в CI — артефакт.
- **Сервер — одно поле, любой вид адреса** (`ServerAddress`, Core): имя, IP (IPv6 в скобках), порт, полный адрес
  EWS, адрес до папки EWS; внутренний и внешний адрес равноправны. `http://` отклоняется с объяснением. Хранится
  полный адрес EWS, в поле показывается короткая запись. Два адреса с автовыбором тогда не делали (YAGNI); по
  просьбе пользователя добавлен необязательный резервный адрес — W3 (часть 5).
- **Окно «Подключение» вместо ручного файла.** Профиль пишет `ConnectionProfileFile.Save` (атомарно, JSON
  вручную — сериализатор экранировал бы «/»), пароль — `WindowsCredentialStore.Save` (`CredWriteW`,
  CRED_PERSIST_LOCAL_MACHINE, буфер пароля затирается). `ConnectionProfileLoader` переименован в
  `ConnectionProfileFile`. Разбор и формат «±ЧЧ:ММ» перенесены в `TargetTimeZone` — одно место правила.
- **«Сохранить» = проверить и сохранить.** Недоступный сервер (до TLS не дошло) — вопрос «сохранить без проверки?»;
  ошибка входа или сертификата — не сохраняем. Принятый при первом подключении сертификат запоминается вместе
  с настройками. Самоподписанный (недоверенный) — показывается с отпечатками SHA-256/SHA-1 и кнопкой «Доверять»;
  смена сертификата — «Доверять» с отдельным предупреждением; перехват антивирусом доверием не лечится. Смена
  сервера сбрасывает прежнее доверие.
- **Сертификат для показа** — `PresentedCertificate` (Core, без X509): валидатор запоминает и отклонённый
  сертификат. `EwsTarget` — единственная точка входа в адаптер; типов EWS Managed API в приложении нет
  (архитектурный тест). Проверка подключения — `GetFolder` календаря с числом элементов.
- **Новые виды ошибок:** `MailboxNotFound` (ErrorNonExistentMailbox); имя сервера не разрешилось — «нет связи».
  Тексты ошибок для человека — `ErrorMessages`, по одному на каждый вид и решение по сертификату (тест полноты);
  значения настроек в тексты не попадают, подробности исключения — свёрнуто, только в окне.
- **Ход работы и остановка.** `CleanupProgress` по этапам («Читаю календарь: N из M», «Удаляю: N из M»).
  Сообщения — синхронными переходниками, `Progress<T>` только в окне: без контекста он переставлял бы сообщения.
  Остановка во время удаления — исход `Cancelled` с точным счётом (а не исключение, теряющее счёт): начатый пакет
  доводится до конца, в порт удаления токен не передаётся. Обрыв порта посреди пакета — `Failure` с сохранённым
  исключением (понятная причина в окне) и счётом.
- **MVVM без библиотек:** `ObservableObject`, `RelayCommand`, `AsyncCommand` (повторный запуск во время операции
  невозможен), доступность кнопок пересчитывается явно, без `CommandManager`. Модели представления без типов
  WPF — 59 тестов без окна. Окна и вопросы — через `IDialogService`/`IConnectionDialog`.
- **Безопасность экрана очистки:** удалить можно только по предпросмотру для текущих параметров и подключения;
  смена параметров сбрасывает его; после удаления он израсходован. Подтверждение — ввод адреса ящика (без учёта
  регистра), окончательное удаление — ещё и отметка; кнопка по умолчанию в окне подтверждения — «Отмена».
  Закрытие окна во время удаления — вопрос, остановка после пакета, затем закрытие.
- **Период по умолчанию — последний месяц** (самый частый случай); это лишь значения полей, без предпросмотра и
  подтверждения ничего не удаляется. Даты вводятся с клавиатуры или в календаре, время — в поясе приёмника.
- **Демонстрационный режим `--demo`** — тот же экран поверх `InMemoryCalendar` с выдуманными данными (2 400 копий,
  серии, исключение, заметка) и небольшими задержками: проверка интерфейса без сервера, в том числе тысяч строк
  и остановки. Манифесты — во временную папку. Полоса «Демонстрационный режим» видна всегда.
- **Один экземпляр** (T5) — именованный мьютекс сеанса. Непредвиденные ошибки — окно с текстом, программа не
  закрывается молча (`DispatcherUnhandledException`, `UnobservedTaskException`).
- **Найдено при проверке окна в демонстрационном режиме и исправлено:** привязка `TwoWay` к свойству только для
  чтения у индикатора хода (падение при старте); неявный стиль `Window` не применяется к окнам-наследникам —
  стиль задаётся явно; числа в заголовках вкладок по-английски («2,441») — язык задаётся стилем окна и
  наследуется фрагментами текста; стандартный шаблон поля даты обрезал год — собственный шаблон из штатных частей.
- **Инструменты разработки** `build\screenshot.ps1`, `build\ui-walk.ps1`, `build\ui-connection.ps1`,
  `build\ui-windows.ps1` — снимки окон и проход сценария через UI Automation. Только ASCII: Windows PowerShell 5.1
  читает UTF-8 без BOM как ANSI.
- **Не передавать кириллицу через строку команды оболочки** при записи файлов: часть заглавных букв терялась
  («акетное» вместо «Пакетное»). Найдено и исправлено в 12 комментариях тестов; файлы правятся только инструментом
  правки.

## W3 (часть 4) — аудит, адаптивные окна, точечная синхронизация

- **Одна проверка сертификата на процесс.** `ServicePointManager.ServerCertificateValidationCallback` —
  глобальный: присваивание своей проверки каждым подключением давало гонку (пробное подключение подменяло проверку
  сеанса) и обход закрепления соединениями из пула. Теперь `TlsTrustRegistry` ставит одну проверку, а она
  выбирает проверку подключения по `HttpWebRequest.ConnectionGroupName`; у каждого `EwsTarget` своя группа
  (проверено по коду EWS Managed API 2.2: имя группы копируется в каждый запрос). Отклонено: подмена глобальной
  проверки на время запроса — гонка остаётся.
- **Повторы — только временные ошибки**, экспоненциально с потолком и с учётом `BackOffMilliseconds` сервера;
  ошибки входа не повторяются (блокировка учётной записи, T3). Проверка подключения — без повторов: человек ждёт
  ответа.
- **Адаптивность — измерением, а не порогом.** `FillPanel` внутри прокрутки отдаёт карточке со списком всё
  свободное место, но не меньше её `MinHeight`; остальные части не сжимаются никогда. Отклонено: Grid с высотой
  «не меньше N» — необходимую высоту остальных частей (сообщения, перенос строк) заранее не знает никто, и при
  ошибке порога кнопка «Удалить» уходила за край без прокрутки. Таблица всегда получает конечную высоту —
  виртуализация строк сохраняется (проверяет тест: из 3 000 строк построено не больше 200).
- **Высокая контрастность — подменой кистей палитры**, а не системными цветами везде: в обычном режиме своя
  палитра с выверенным контрастом, в контрастном — цвета пользователя. Слежение — `SystemParameters` и
  `SystemEvents.UserPreferenceChanged` (смена одной контрастной темы на другую).
- **Озвучивание** — событие `LiveRegionChanged` из обработчика свойства `Announce.Text` (без подписок,
  удерживающих элементы в памяти); только заголовки сообщений, не счётчик хода работы.
- **Тесты окон — настоящие окна** в одном потоке окон за пределами экрана; тесты в основном домене процесса
  (выгрузка отдельного домена с работающим потоком окон роняла процесс тестов).
- **Точечная синхронизация за период** (`Core.Sync.SyncPlanner`, чистая функция) — правила в PLAN.md §5.
  Опознание копии — только по метке `IwoBridgeSourceId`; изменение — по отпечатку `IwoBridgeContentHash`
  (SHA-256 канонической записи, версия «v1»). Отклонено: сравнение по времени изменения в приёмнике — правка копии
  сервером (например, пересчёт пояса) давала бы ложные перезаписи. Неполный снимок источника не удаляет ничего;
  массовое удаление — только с подтверждением.
- **Второй (резервный) адрес сервера** — сделан в W3 (часть 5), см. ниже.

## W3 (часть 5) — резервный адрес сервера

- **Необязательное поле, тот же сервер.** `ConnectionProfile.AlternateEwsUrl` и свой
  `AlternatePinnedCertificateThumbprint`; `Endpoints` — адреса в порядке попытки (`ServerEndpoint`). Резервный с
  тем же хостом и портом отклоняется: это тот же сервер TLS, пользы нет. Отпечаток без адреса — ошибка, а не
  тихий пропуск. Старые файлы настроек читаются как раньше (поля необязательны).
- **Закрепление сертификата — у каждого адреса своё.** Внутренний адрес обычно отвечает собственным сертификатом
  Exchange, внешний — сертификатом публичного центра или прокси. В `EwsTarget` у каждого адреса своя группа
  соединений и свой валидатор в `TlsTrustRegistry`; в окне доверие хранится по ключу «хост:порт» адреса.
- **Переход — только при недоступности адреса** (`ErrorClassifier.IsUnreachable`: обрыв или отказ соединения,
  имя не разрешилось, нет ответа). Ошибки входа, прав, сертификата, TLS и «сервер занят» адрес не меняют: тот же
  сервер ответил бы так же, а повтор входа с неверным паролем приближает блокировку (T3).
- **Переход — внутри шлюза, до повторов.** `EwsCalendarGateway` получает сервисы всех адресов; недоступный адрес →
  тот же запрос сразу по следующему, и шлюз остаётся на работающем адресе. Повторы с паузами (`RetryPolicy`)
  оборачивают попытку с переходом снаружи: недоступный основной не задерживает работу на время всех попыток.
  Переход безопасен посреди работы: за адресами один ящик, чтения ничего не меняют, удаление идемпотентно.
  Отклонено: выбор адреса пробным запросом при открытии сеанса — сеанс открывается без сети, а связь может
  пропасть и позже, посреди очистки.
- **Проверка в окне — каждого адреса отдельно** (`ConnectionProfile.ForEndpoint`): у каждого свой сертификат и
  своя доступность. Сохранение: ответивший с ошибкой адрес — не сохраняем; один недоступный — нормально;
  недоступны все — вопрос «сохранить без проверки?». Доверие («Доверять этому сертификату») относится к адресу,
  чей сертификат показан.
