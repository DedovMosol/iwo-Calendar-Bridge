# Архитектура

<div align="justify">

Документ описывает устройство кода: слои, порты, адаптеры, потоки данных и основные решения. Схемы приведены
на языке Mermaid и отображаются на GitHub.

## Принципы

- **Порты и адаптеры.** Ядро не зависит от внешних систем. EWS, Outlook и календарь в памяти подключаются
  через порты, зависимости направлены внутрь, к ядру.
- **Разделение ответственности.** `IwoBridge.Core` не ссылается на EWS, COM и WPF. Время нормализуется в
  `TimeMapper`, пояс и границы периода считает `TargetTimeZone`, попадание в период определяет `TimeWindow`.
- **Одно правило — одна реализация.** Попадание в период, полнота ответов, оценка пакетного удаления,
  классификация ошибок, отпечаток содержимого, разбиение на пакеты.
- **Простота.** Планирование очистки и синхронизации — чистые функции от прочитанных данных. Порты появляются
  вместе с адаптерами, которые их реализуют.
- **Сначала чтение, затем запись.** Изменения выполняются по полностью прочитанным данным и в объёме,
  который подтвердил пользователь или правило автокопирования.

## 3. Ядро

| Область | Типы | Назначение |
|---|---|---|
| Time | `TimeMapper`, `TargetTimeZone`, `TimeWindow` | Нормализация к UTC, пояс календаря из профиля, границы периода, правило попадания в период |
| Model | `TargetItemInfo`, `TargetOccurrence`, `OccurrenceSpan`, `ItemKind` | Неизменяемые описания элементов приёмника и экземпляров серий, время в UTC |
| Configuration | `ConnectionProfile`, `ServerEndpoint`, `ServerAddress` | Адрес EWS и резервный адрес (у каждого свой отпечаток), ящик, смещение пояса |
| Transport | `Thumbprint`, `CertificateFingerprint`, `CertificatePinningPolicy` | Нормализация и сравнение отпечатков SHA-1 и SHA-256, первое закрепление, распознавание HTTPS-инспекции |
| Security | `CredentialSecret`, `ICredentialStore` | Учётные данные (домен отдельно для NTLM) и порт их хранилища |
| Errors | `OperationErrorKind`, `ErrorClassifier`, `RetryPolicy` | Классификация, повторы временных ошибок с паузами 1, 2, 4… с (до 60 с или по подсказке сервера), признаки «остановить пакет» и «нужен человек» |
| Reading, Paging | `CalendarSnapshotReader`, `CompletenessGuard`, `BatchDeleteOutcome` | Постраничный обход с якорем и повтором при сдвиге, строгая проверка полноты чтения и удаления |
| Cleanup | `CleanupPlanner`, `CleanupExecutor`, `CleanupPlan` | Планирование очистки и пакетное удаление |
| Sync | `SourceItem`, `RecurrenceRule`, `SyncContent`, `MapiRtf`, `EventCategories`, `CopyRules`, `SyncPlanner`, `OwnEventMatcher`, `ISourceCalendar`, `ICopyTarget` | Модель события источника, отпечаток содержимого, категории, правила для личных событий, план синхронизации, сверка с событиями пользователя |

Логика ядра — чистые функции и неизменяемые типы. Изменяемое состояние есть только в адаптерах и приложении,
и доступ к нему упорядочен (семафор канала EWS, поток STA Outlook, поток интерфейса).

## 4. Копирование

```mermaid
sequenceDiagram
  actor U as Пользователь или расписание
  participant VM as CopyViewModel
  participant Run as CopyRunner
  participant Dst as ICopyTarget (EwsCopyTarget)
  participant Src as ISourceCalendar (Outlook или EWS)
  participant Plan as SyncPlanner

  U->>VM: предпросмотр (F5) или запуск по расписанию
  VM->>Run: PreviewAsync(период)
  Run->>Dst: ReadCopiesAsync — копии с метками
  Run->>Src: ReadAsync — события периода и события, на которые ссылаются копии
  Run->>Run: CopyRules — правило для личных событий
  Run->>Plan: Plan(источник, копии, пороги)
  Plan-->>Run: Create, Update, Recreate, Delete
  Run->>Dst: ReadOwnEventsAsync — события пользователя (если есть что создавать)
  Run-->>VM: план, рекомендованные действия, замечания
  U->>VM: выбор строк и подтверждение (вручную)
  VM->>Run: RunAsync(выбранные действия)
  loop по одному действию
    Run->>Src: LoadAttachmentsAsync (если есть вложения)
    Run->>Dst: Create / Update / Delete
  end
  Run-->>VM: итог и сбои по событиям
```

- **Сопоставление.** Копия хранит `IwoBridgeSourceId` и `IwoBridgeContentHash` (extended properties). Если
  отпечаток изменился, копия перезаписывается. Серия при изменении пересоздаётся. Копии, которых больше нет в
  источнике, удаляются.
- **События пользователя.** `OwnEventMatcher` сравнивает новые события с событиями приёмника без меток (вид,
  начало, конец, тема). Совпадения не входят в рекомендованные действия.
- **Пороги.** План с большим числом удалений выполняется только после явного подтверждения. Если источник
  прочитан не полностью, план строится без удалений.
- **Запись в EWS.** Событие создаётся с отметкой «не дописано», затем добавляются вложения (по одному запросу на
  файл) и исключения серии, отпечаток пишется последним запросом. Сбой на любом шаге удаляет созданное, копия с
  отметкой «не дописано» перезаписывается при следующем запуске. Серия пересоздаётся в обратном порядке: сначала
  новая копия, затем удаление прежней. Время пишется в поясе календаря приёмника (`CalendarZones`, классические
  ID зон Windows), описание — исходным RTF (`MapiRtf`).
- **Категории.** `SourceItem.Categories` — названия категорий события, `SourceException.Categories` — свои
  категории повторения (`null`, если они те же, что у серии). Источник Outlook читает многозначное
  `PidNameKeywords`, EWS — `item:Categories`. Цвета из списка категорий источника (`SourceRead.CategoryColors`)
  идут только в подсказку предпросмотра (`CopyPreview.Categories`): список категорий приёмника EWS Exchange 2007
  не открывает, и программа его не меняет. В отпечаток категории входят, только если они есть.
- **Период «всё время».** `CopySettings.AllTime` задаёт окно `TargetTimeZone.MinPeriodDate`…`MaxPeriodDate`.
  Чтение источника и приёмника перечисляет папку целиком и отбирает события по окну у себя, без `CalendarView`,
  поэтому окно в тысячи лет не упирается в ограничения `CalendarView` на диапазон и число повторений.
- **Замечания к записи.** `ICopyTarget.CreateAsync` и `UpdateAsync` возвращают то, что перенести нельзя (изменённое
  повторение, которого нет в серии копии, или категории серии, которые не снимаются у одного повторения). Копия записана и считается актуальной, `CopyResult.Remarks` показывает
  замечание один раз, повторной записи на следующих запусках нет.
- **Сбои по событиям.** Ошибка входа, прав, сертификата или TLS останавливает пакет сразу. Ошибка соединения,
  таймаут, квота и `ServerBusy` останавливают его, если повторились на следующем событии подряд. Остальные
  ошибки относятся к своему событию и попадают в итог.
- **Остановка.** «Остановить» прерывает чтение сразу, запись — после текущего события.

## 5. Автокопирование

```mermaid
stateDiagram-v2
  [*] --> Ожидание: включено
  Ожидание --> Запуск: таймер
  Запуск --> Ожидание: занято другим — через минуту
  Запуск --> Копирование: свободно
  Копирование --> Ожидание: готово — через интервал
  Копирование --> Пауза: вход, права, сертификат
  Пауза --> Ожидание: подключение изменено
  Ожидание --> [*]: выключено
```

`AutoCopyViewModel` ведёт расписание на однократном `DispatcherTimer`: следующий запуск назначается после
окончания текущего. Сам запуск выполняет `CopyViewModel.RunScheduledAsync`. Он ждёт, если идёт другая
операция или открыт модальный диалог, перечитывает список календарей Outlook и сдвигает период от текущей
даты. Календарь Outlook выбирается по EntryID папки. После сна и смены системного времени запуск назначается
через минуту (`SystemResumed`). `TrayIcon` показывает значок, меню и уведомления о проблемах.
`RegistryAutostart` пишет запуск с ключом `--tray` в `HKCU\…\Run` и обновляет путь, только если записанный
файл программы больше не существует.

## 6. Очистка

```mermaid
sequenceDiagram
  actor U as Пользователь
  participant VM as CleanupViewModel
  participant Run as CleanupRunner
  participant Snap as CalendarSnapshotReader
  participant Ews as EwsCalendarGateway
  participant Plan as CleanupPlanner
  participant Man as CsvCleanupManifestWriter

  U->>VM: объём и период
  VM->>Run: PreviewAsync
  loop страницы FindItem с якорем
    Snap->>Ews: ReadPageAsync
  end
  opt период и серии
    Run->>Ews: данные серий (GetItem) и экземпляры окна (CalendarView)
  end
  Run->>Plan: BuildPlan
  Run-->>VM: «Будет удалено» и «Останется»
  U->>VM: подтверждение вводом адреса ящика
  VM->>Run: RunAsync
  Run->>Run: свежий снимок и план, удаляется пересечение с подтверждённым
  Run->>Man: манифест до первого удаления
  loop пакеты по 50
    Run->>Ews: DeleteItems, SendToNone
  end
  Run-->>VM: итог
```

Серия целиком в периоде удаляется мастером. Серия на границе периода обрезается удалением экземпляров внутри
периода (по UID, с учётом перенесённых исключений). Неполное чтение на любом шаге оставляет календарь без
изменений. Отказ сервера по отдельным элементам (`BatchDeleteOutcome.FinishedWithRefusals`) не прерывает
очистку: обе фазы проходят до конца, `CleanupResult.RefusedCount` называет число отказов. Обрыв пакета или
несопоставимый ответ останавливают удаление сразу.

## 7. Проверка сертификата

```mermaid
flowchart TB
  A["Соединение"] --> H{"Группа соединений подключения EWS?"}
  H -->|нет| STD["Стандартная проверка Windows"]
  H -->|да| B{"Отпечаток закреплён?"}
  B -->|да| C{"Совпал SHA-1 или SHA-256?"}
  C -->|да| OK1["Принять"]
  C -->|нет| R2["Отклонить: другой сертификат"]
  B -->|нет| E{"Издатель — HTTPS-инспекция?"}
  E -->|да| R1["Отклонить: перехват"]
  E -->|нет| F{"Цепочка доверенная?"}
  F -->|да| OK2["Принять и закрепить SHA-256"]
  F -->|нет| R3["Показать сертификат пользователю"]
```

`TlsTrustRegistry` регистрирует одну проверку на процесс и выбирает правило по группе соединений запроса. У
каждого адреса каждого подключения своя группа и своё закрепление. Несовпадение имени в сертификате с адресом
допускается, так как к серверу часто подключаются по IP.

## 8. Адаптеры

- **EWS (`IwoBridge.Ews`).** `EwsTarget` — единственная точка входа приложения. Он создаёт сервисы для каждого
  адреса, канал чтения в UTC и канал записи в поясе календаря. `EwsChannel` выполняет запросы по одному
  (семафор), переходит на резервный адрес при сетевой недоступности и повторяет временные ошибки по
  `RetryPolicy`. Каналы чтения и записи одного подключения переходят на резервный адрес вместе. Создание события
  и добавление вложения не повторяются, на резервный адрес переходят, только если запрос не ушёл
  (`RunOnceNonIdempotentAsync`). Ошибка элемента из ответа DeleteItems (`EwsItemErrorException`) сохраняет код
  сервера и классифицируется как исключение EWS. `EwsPaging` читает страницы с перекрытием на один элемент: первый
  элемент страницы должен совпасть с последним прочитанным, иначе перечень сдвинулся и читается заново. Схема
  запросов — `Exchange2007_SP1`, она поддерживается серверами 2007 SP1 … 2013. Протокол TLS выбирает Windows.
- **Outlook (`IwoBridge.Outlook`).** Позднее связывание COM, вызовы по одному в потоке STA (`StaWorker`) с
  фильтром сообщений, у потока свой объект `Outlook.Application`. Вызов ограничен по времени без признаков
  работы (10 минут), зависший поток заменяется новым. Пока жив один зависший поток, следующий не заводится,
  вызовы сразу получают ошибку. После перезапуска Outlook подключение восстанавливается. Таблица папки
  (`GetTable`) даёт быстрый перечень, затем открываются только отобранные события. Каждый объект COM
  освобождается сразу (`Com.Release`).
- **В памяти (`IwoBridge.InMemory`).** Реализует те же порты и воспроизводит поведение EWS на границах:
  перечисление без данных серий, надмножество CalendarView, удаление мастера и экземпляра, отсутствующий id.

## 9. Приложение с окнами

Exe `IwoCalendarBridge`, .NET Framework 4.8, Windows 7 SP1+, x86 и x64. Корень композиции — `App`, только
там создаются реальные реализации портов. Модели представления не используют типы WPF и тестируются без окна.

| Слой | Типы | Назначение |
|---|---|---|
| Модели представления | `MainViewModel`, `CopyViewModel`, `AutoCopyViewModel`, `CleanupViewModel`, `ConnectionViewModel`, `AccountsViewModel`, `DeletionConfirmationViewModel`, `HistoryViewModel`, `ConsoleViewModel` | Вкладки, подключения, учётные записи, копирование, расписание, очистка, подтверждения, история операций, консоль |
| Службы | `ITargetSession`, `ITargetConnector`, `ISettingsStore`, `IMailboxStores`, `ICopySettingsStore`, `IOutlookCalendars`, `IOneShotTimer`, `IAutostart`, `IDialogService`, `ConsoleOutput` | Сеть, файлы, Outlook, таймер, реестр, окна и консоль за портами |
| Окна | `MainWindow`, `CopyPage`, `ConsolePanel`, `ConnectionWindow`, `AccountsWindow`, `ConfirmDeletionWindow`, `QuestionWindow`, `HelpWindow`, `HistoryWindow`, `TrayIcon` | Разметка, в коде окон только то, что требует WPF |
| Вид | `FillPanel`, `WindowSizing`, `Theme`, `Announce` | Адаптивная страница, окна в пределах экрана, высокая контрастность, озвучивание |

Учётными записями владеет `MainViewModel`: у него сеансы приёмника, источника и добавленной почты, и после
изменения он же переключает копирование и список очистки. Окно «Учётные записи» обращается к нему через
внутренний порт `IAccountManager` (список строк, добавить, изменить, забыть пароль, удалить). «Забыть пароль»
сначала пишет имя учётной записи в профиль, затем удаляет пароль из Credential Manager. Сеанс работает до
выхода, следующий запуск спросит пароль. Удаление приёмника или источника отключает его в копировании и
очистке и освобождает сеанс.

Шрифт всех окон задаёт стиль `AppWindow` (Times New Roman). Кегль, жирность и цвет заголовка вкладки операции
заданы на его `ContentPresenter`, а не на `TabItem`: содержимое вкладки — логический потомок `TabItem` и
унаследовало бы их.
| Тексты | `ErrorMessages`, `UserMessage`, `RussianText` | «Что случилось, что делать, подробности» для каждого вида ошибки, числа, даты, склонения |

## 10. Журнал операций

```mermaid
flowchart LR
  VM["CopyViewModel · CleanupViewModel"] -->|итог с экрана| OH["OperationHistory"]
  OH --> LOG(["IOperationLog"])
  LOG -->|хранение| JL["JsonLinesOperationLog — logs/history.jsonl"]
  LOG -.->|запуск из консоли| MIR["MirroredOperationLog"]
  LOG -->|всегда| PANE["MirroredOperationLog → ConsoleViewModel · ConsolePanel — консоль внизу окна"]
  MIR --> CON["ConsoleOutput — консоль Windows или файл перенаправления"]
  JL -->|Recorded, Recent| HW["HistoryViewModel · HistoryWindow"]
```

| Тип | Назначение |
|---|---|
| `OperationRecord` | Законченная операция: вид (копирование, автокопирование, очистка), начало и конец в UTC, итог (готово, есть проблемы, остановлено), откуда и куда, период, счётчики, заголовок итога и до 50 строк подробностей |
| `IOperationLog` | Порт журнала: `Record`, `Info` (ход работы, только для консоли, с признаком проблемы), `Recent`, событие `Recorded` |
| `OperationLine`, `OperationRecordText.Lines` | Строки консоли с видом (ход работы, готово, проблема, остановлено, подробность) — один формат для окна и консоли Windows |
| `ConsoleViewModel`, `ConsolePanel` | Панель внизу главного окна: строки из любого потока — в поток окна, последние 1000 строк, цвет по виду строки, сворачивание, «Копировать всё» |
| `JsonLinesOperationLog` | Файл JSON Lines: UTF-8 без BOM, время ISO 8601 в UTC, версия схемы в поле `v`. Строка дописывается в конец файла, повреждённая строка при чтении пропускается. Файл больше 1 МБ переносится в `history.1.jsonl` |
| `MirroredOperationLog` | Декоратор: каждая запись и каждое сообщение о ходе работы строками в получатель — панель окна или `TextWriter` консоли Windows (там типографские знаки заменены на ASCII) |
| `MemoryOperationLog` | Журнал в памяти для демонстрационного режима и тестов |
| `ConsoleOutput` | Вывод перенаправлен в файл — UTF-8. В канал — кодовая страница консоли, которой канал читают. В `nul` — вывода нет. Консоль запустившего процесса — `WriteConsoleW`, программа подключается к ней только на время строки, Ctrl+C и Ctrl+Break поглощает. Строки пишет фоновый поток из очереди на 1000 строк: остановленная консоль или непрочитанный канал не задерживают поток окон |
| `OperationHistory`, `HistoryViewModel`, `HistoryWindow` | Запись итога вкладок тем же текстом, что на экране, и немодальное окно «История» (Ctrl+H): последние 1000 операций, новые сверху, итог за 7 дней, подробности выбранной строки |

Журнал ведёт только законченные операции. Сбой записи файла операцию не прерывает и уходит в трассировку. Запуск
расписания, перенесённый из-за другой операции, не записывается. Запуск, который не начался из-за настройки (нет
приёмника, календарь не найден), записывается как проблема.

## 11. Тестирование

- **Ядро и сценарии** — на синтетических данных и календарях в памяти.
- **EWS** — мапперы, ошибки, правила повторения, проверка сертификата на сгенерированных сертификатах,

- **Окна** — модели представления без окна, расписание на подставном таймере, разметка в настоящих окнах вне

  для UI Automation).

- **CI** — восстановление пакетов по lock-файлам, сборка Release, тесты, упаковка x86 и x64.
