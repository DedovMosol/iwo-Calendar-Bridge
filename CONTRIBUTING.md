# Участие в проекте

Спасибо, что хотите помочь. Несколько правил, которые держат проект безопасным для чужих календарей.

## Перед изменением

- Прочитайте [архитектуру](docs/ARCHITECTURE.md) и [журнал решений](docs/DECISIONS.md): многие «очевидные»
  упрощения уже рассматривались и отклонены — там написано почему.
- Правила безопасности не ослабляются: удаление только по полностью прочитанному календарю и только
  показанного в предпросмотре, ошибка входа не повторяется, сертификат закрепляется.

## Код

- C#, .NET Framework 4.8 (Windows 7 SP1+). Принципы: DRY, KISS, SOLID, YAGNI, разделение ответственности.
- Ядро (`IwoBridge.Core`) — без ввода-вывода и сети; типы EWS — только в `IwoBridge.Ews`; WPF — только в
  `IwoBridge.Wpf`. Это проверяют архитектурные тесты.
- Комментарии — по-русски, о том, зачем код такой; тексты для пользователя — в `Messages/ErrorMessages.cs`.
- Скрипты `build\*.ps1` — только ASCII: Windows PowerShell 5.1 читает UTF-8 без BOM как ANSI.

## Данные

- **Никаких данных организаций**: адресов серверов, ящиков, имён, отпечатков сертификатов — ни в коде, ни в
  тестах, ни в документах, ни в снимках экрана. Только синтетические домены `example.test` / `example.com`.
- Снимки экрана — только из демонстрационного режима (`--demo`).

## Проверка

```powershell
dotnet build IwoBridge.sln
dotnet test  IwoBridge.sln
```

Новое поведение — с тестами; исправление ошибки — с тестом, который падал до исправления. После изменения
`PackageReference` выполните `dotnet restore IwoBridge.sln` и закоммитьте lock-файлы.
